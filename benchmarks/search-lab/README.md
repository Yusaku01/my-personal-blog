# ブログ検索の比較記録

2026-09-28時点の日本語記事70件を対象に、`main` の現行検索と、Jev、Cloudflare AI Search、Orama、Pagefind、Fuse.jsを比較する。各方式のローカル起動方法は各ブランチの `SEARCH_LAB.md` に記載する。Algoliaはアカウント登録時の GitHub OAuth 認可が自動承認審査で止まったため、今回の実測から外した。

比較画面: [現行](http://127.0.0.1:4331/blog/) / [Jev](http://127.0.0.1:4332/search-lab/) / [Cloudflare AI Search](http://127.0.0.1:4333/search-lab/) / [Orama](http://127.0.0.1:4334/search-lab/) / [Pagefind](http://127.0.0.1:4335/search-lab/) / [Fuse.js](http://127.0.0.1:4336/search-lab/)。現時点では6画面ともローカルで起動中。Workerを停止した後は各ブランチの手順で再起動する。

## 測り方

`node scripts/benchmark-search-lab.mjs` で、起動済みの各ページを同じ Chromium から操作する。最初の `mise` 検索を初回値として記録し、その後は固定した13クエリを各3回実行する。入力送信から結果表示までのブラウザ内の経過時間を測り、計39回の平均・中央値・90パーセンタイルを出す。通信を使う方式の時間にはAPI往復を含む。ページ読み込み時間は含まない。

語クエリは `Web Worker`、`コンテナクエリ`、`プリフェッチ`、`翻訳`、`キャッシュ`、`View transitions`、`CSS変数`、`mise`、`Lukurauha`、`ルーティング` の10件。現行の検索用JSONに語が含まれる記事を正解集合として固定する。上位3件の的中数を各クエリの `min(3, 正解記事数)` の合計で割り、最初の正解記事が何位に出たかを表す MRR も算出する。自然文は「Astro のページを事前に読み込む方法」「ブログ記事を速くビルドしたい」「読書アプリを作った話」の3件で、0件応答の数と上位結果を確認する。関連度の集計も3回の結果をすべて使う。

この正解集合は文字列一致で作るため、同じ文字列包含方式の現行検索に有利である。言い換えや関連概念を返す精度はこの数値だけでは評価できない。自然文の結果は、検索意図に合う記事を別途人手で確認する。初回値は既存検索がページ初期化時に索引を読み、OramaとFuse.jsが初回検索時に索引を作るため、処理の開始条件が異なる。ローカルでの少数回計測なので、本番利用者の応答時間や90パーセンタイルを推定する用途には使わない。

記事 URL の順位は、本文の答えを読者が発見できたかを表さない。答えのある質問5件と答えのない質問1件を使った追加計測、実際の操作での記録方法は[情報到達の評価](task-evaluation.md)に分けた。

この方法は、同一コーパス・固定クエリ・上位的中数・MRR・自然文の0件率を使った[参考記事](https://hk-it.hatenablog.com/entry/2026/08/05/210424)を、このブログ向けに縮小したもの。上位の関連度評価には[OpenSearch の検索品質評価](https://docs.opensearch.org/latest/search-plugins/search-relevance/evaluate-search-quality/)で使われる Precision@k と MRR の考え方も参考にした。手動のUX確認では、検索開始から記事を開くまで、0件表示、外部記事への遷移、キーボードとスマートフォンでの操作も見る。

Orama の比較実装は[参考 PR #157](https://github.com/h-kono-it/kouno-log/pull/157/changes)の日本語 tokenizer、タイトルの重み付け、全語一致から緩い検索への切り替えを参照した。比較画面のUIは、このブログの既存記事カードに合わせている。

## 結果

2026-09-28、macOS のローカル Chromium と Wrangler で計測した。平均・中央値・p90 は各13クエリ×3回の39回。初回は別に `mise` を1回検索した値である。単位はミリ秒。数値はブラウザの DOM 更新完了までで、画面の実描画やページ初期ロードは含まない。

| 方式                 | 初回 | 2回目以降の平均 / 中央値 / p90 | 語クエリ上位3件の的中 | 語クエリ MRR | 自然文上位3件の的中 | 自然文0件 |
| -------------------- | ---: | -----------------------------: | --------------------: | -----------: | ------------------: | --------: |
| 現行                 |  7.2 |                1.7 / 1.6 / 1.8 |                 60/60 |        1.000 |                 0/9 |       9/9 |
| Jev                  |  747 |               794 / 687 / 1218 |                 39/60 |        0.633 |                 8/9 |       0/9 |
| Cloudflare AI Search | 9287 |             1945 / 1073 / 4906 |                 42/60 |        1.000 |                 6/9 |       0/9 |
| Orama（文字 bigram） |  124 |                0.4 / 0.3 / 0.7 |                 60/60 |        0.950 |                 3/9 |       0/9 |
| Pagefind             |  117 |               4.1 / 1.7 / 14.9 |                 57/60 |        1.000 |                 0/9 |       9/9 |
| Fuse.js              |   39 |             17.4 / 13.8 / 28.7 |                 54/60 |        0.933 |                 3/9 |       6/9 |

自然文の正解記事は `Astro のプリフェッチ記事`、`cacheDir の最適化記事`、`Lukurauha の紹介記事` とし、[生データ](results.json)の `intentGold` に具体的な URL を残した。この3件は少数の探索的な評価で、正解記事の選定も計測結果を見ながら行った。順位を確定評価するには、検索結果を見る前に別のクエリと正解集合を固定して再計測する必要がある。Jev は最初と最後の自然文で目的の記事を1位に出した。Cloudflare AI Search は最初を1位、最後を2位に出した。Jev は2回目と3回目に「ブログ記事を速くビルドしたい」の `cacheDir` 記事を3位に出した。自然文で0件を返さない方式でも、上位の内容が役立つとは限らない。

現行検索と Orama は語の厳密一致に強く、Orama は日本語の複合語を比較的速く処理した。Pagefind もほぼ同じ的中数で、索引の分割読み込みを自動で行う。Jev は自然文で記事を見つけやすい一方、TypeSafe と Cloudflare Vectorize への通信が必要。自然文2件では3回の測定中に上位3件の順序や構成が変わり、ほかの方式は今回の測定で変わらなかった。Cloudflare AI Search は今回のローカル計測で応答のばらつきが大きかった。これは比較用の限られた実測で、実運用の選定は手動の操作感と本番に近い環境でも確認する。

生データには各クエリの結果 URL、3回の経過時間、エラー数を保存した。計測時のエラーは全方式で0件だった。

## 手動で見る項目

1. 同じ検索語で、最初の3件から目的の記事を迷わず選べるか。タイトル・出典・説明の分かりやすさも見る。
2. 初回検索と2回目以降の待ち時間、検索中の表示、0件時の表示を確認する。
3. 日本語の複合語、英数字、自然文、誤字で結果の違いを確認する。
4. キーボードだけで入力・送信・結果リンクへ移動し、外部記事が正しいURLで開くかを見る。
5. スマートフォン幅で入力欄、ボタン、記事カードの読みやすさと横スクロールを確認する。

比較ページ5つは同じ入力欄と記事カードを使う。現行の `/blog/` には検索履歴や記事タブがあり、ページ構成自体も異なるため、操作感の差は検索エンジンだけの効果として扱わない。Orama の日本語・英語画面で検索を実行し、デスクトップと390px幅の表示を目視確認した。390px幅で横スクロールは発生せず、キーボードの Enter で検索でき、外部記事へのリンクも正しかった。スクリーンリーダーでの操作は未確認。

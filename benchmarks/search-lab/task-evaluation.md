# 欲しい情報にたどり着けるかの評価

## 今回の数値が示す範囲

既存の[検索比較](README.md)は、結果表示までの時間と「記事の URL が上位にあるか」を測る。記事本文にある答えを読者が発見・理解できたかは測っていない。3回の同一検索は結果の安定性を見るための反復であり、独立した3人の成功例ではない。

現行と5つの比較画面はいずれも記事カードにタイトル・日付・タグを表示する。本文の一致箇所、答えを含む抜粋、ハイライトは表示しない。そのため、正解記事が1位に出ても、一覧で答えが提示されたとは判定しない。

## 実際に読者が答えを得られるか

上の表は記事到達の代理指標として使い、次はタスクを渡して手動で操作する。各方式で同じ課題を試し、答えを見つけた記事と、その本文の根拠を記録する。答えを見つけられない場合も結果として残す。

1. [比較画面](README.md#ブログ検索の比較記録)を開き、[課題だけのページ](task-prompts.md)から1問を読む。上の質問文と正解欄は検索を終えるまで見ない。自分ならどう探すかで最初の語を入力する。
2. 検索開始から、本文を見て答えを確信するまでを計る。2分でいったん打ち切り、未完了とする。答えのない課題は、根拠なく記事から日付を推測せず「このブログには答えがない」と判断できた場合に成功とする。
3. 1課題ごとに、方式・最初の検索語・言い換え回数・開いた記事数・最初に開いた記事・結果カードだけで答えが分かったか・答えの正否・完了時間を記録する。正否は[本文の根拠](task-cases.json)と照合する。
4. 同じ人が6方式を続けて使うと、最初の方式で答えを覚える。方式の順序を課題ごとに変え、可能なら初見の協力者にも試してもらう。1人だけの結果は探索的な観察として扱う。

記録例（各方式と各課題につき1行を追加）:

| 方式 | 課題ID | 初回検索語 | 言い換え | 開いた記事 | 最初の記事は適切か | 一覧に答えが見えたか | 答えは正しいか | 完了秒数 / 未完了 |
| ---- | ------ | ---------- | -------: | ---------: | ------------------ | -------------------- | -------------- | ----------------- |
|      |        |            |          |            |                    |                      |                |                   |

主指標は**答えの正答率**と**答えに至る時間の中央値**。補助指標は最初の記事の適切さ、言い換え回数、開いた記事数、答えのない課題の扱いとする。検索結果が表示されるまでの時間は既存ベンチマークで別に測る。これらを揃えて初めて、検索方式の速さと「欲しい情報を得られるか」を合わせて比較できる。

## 現行＋Jev、Orama＋Jev を比べる前に

2つの組み合わせはまだ実装・計測していない。組み合わせ方も結果を変える。例えば0件のときだけ Jev を呼ぶ方式では、長文に0件を返す現行検索を補える可能性がある。一方、Orama は今回の5問で目的の記事が上位3件にない場合も結果自体は返していたため、0件だけを条件にすると Jev は呼ばれない。

組み合わせを比較するときは、発火条件、表示順、最初の結果と追加結果の切り替え、Jev を呼ぶ回数、待ち時間、答えのない質問での誤誘導を同じ課題で測る。まず手動評価で利用者がつまずく箇所を見てから実装を決める。単独方式の平均値を足しても、組み合わせ後の体験や費用は分からない。
